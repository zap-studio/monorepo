# Zap Studio

Zap Studio is a set of type-safe, framework-agnostic, and composable TypeScript packages for core app capabilities — typed HTTP calls, authorization policy checks, retry policies, schema validation, logging, and webhook processing.

Install one package or all six — nothing here depends on the rest of the family.

## Motivation

For each of these problems — typed HTTP calls, authorization, retries, validation, logging, webhooks — most teams do not start from zero. They pick a general library, or write a small wrapper by hand, and move on.

The problem is that these ad hoc solutions tend to skip the hard parts: raw `fetch` does not validate response bodies, hand-written retry loops skip jitter and cancellation, hand-written authorization checks spread through the codebase with no single place to audit them, and hand-written webhook signature checks often use `===` instead of a constant-time comparison, which is a real security gap.

These wrappers are also often built for Node only, so they silently break the moment the code needs to run on an edge runtime or in the browser.

Zap Studio packages solve each of these problems once, correctly, so you do not have to solve them again per project. They share the same foundations — [Standard Schema](https://standardschema.dev) for validation, standard web APIs like `fetch`, `Request`/`Response`, and `AbortSignal` instead of Node-specific ones, and a common, optional `Logger` interface — so they compose cleanly and stay small.

Install one package or all six: each one is type-safe, framework-agnostic, and tree-shakeable on its own.

If you already know [Effect](https://effect.website), much of what Zap Studio covers overlaps with it — typed errors, retries, schema validation. Effect is a full ecosystem built around its own runtime and effect type, and that investment pays off in large production systems that need that level of control.

Zap Studio stays closer to plain TypeScript/JavaScript: no new runtime or mental model to learn, a shallower learning curve, and small composable packages you adopt one at a time — a better fit when you don't need everything Effect brings.

```ts
import { api } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.email(),
});

// `user` is typed from UserSchema — no manual annotations, no `as` casts
const user = await api.get("https://api.example.com/users/1", UserSchema);
```

## Design Principles

Every package follows the same rules:

- **Type safety.** Types come from your schema via [Standard Schema](https://standardschema.dev), not hand-written annotations.
- **Framework-agnostic.** Built on standard runtime APIs — `fetch`, `Request`/`Response`, `AbortSignal`.
- **Composable.** Combine packages as needed — wrap a `fetch` call in a `retry` policy, validate a webhook with `validation`.
- **Tree-shakeable.** Standalone functions, no shared state — unused exports drop out of your bundle.
