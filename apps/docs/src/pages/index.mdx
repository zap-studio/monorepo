# Zap Studio

Zap Studio is a set of type-safe, framework-agnostic, and composable TypeScript packages for core app capabilities — typed HTTP calls, authorization policy checks, retry policies, schema validation, and webhook processing.

Install one package or all five — nothing here depends on the rest of the family.

```ts
import { api } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.email(),
});

// `user` is typed from UserSchema — no manual annotations, no `as` casts
const user = await api.get("https://api.example.com/users/1", UserSchema);
```

## Design Principles

Every package follows the same rules:

- **Type safety.** Types come from your schema, not from hand-written annotations. `@zap-studio/fetch` infers response types from a [Standard Schema](https://standardschema.dev); a mismatched response throws a `ValidationError` instead of shipping bad data further into your app.
- **Framework-agnostic.** Packages rely on standard runtime APIs — `fetch`, `Request`/`Response`, `AbortSignal` — not a specific framework. `@zap-studio/webhooks` routes on the raw `Request`/`Response` primitives, so it runs unchanged on Bun, Deno, Cloudflare Workers, or a Next.js route handler.
- **Composable.** Packages are building blocks you combine as needed: wrap an `@zap-studio/fetch` call in an `@zap-studio/retry` policy, or validate a webhook payload with the same `@zap-studio/validation` helper that `permit` uses internally for resources.
- **Tree-shakeable.** Every export is a standalone function with no side effects and no shared internal state — unused exports are dropped entirely by any modern bundler. Prefer function composition over class inheritance so only the code paths you actually call end up in your bundle.

## Packages

| Package | What it covers |
| --- | --- |
| [`@zap-studio/fetch`](/fetch) | Type-safe HTTP requests with schema-validated responses |
| [`@zap-studio/permit`](/permit) | Declarative authorization policies and permission checks |
| [`@zap-studio/retry`](/retry) | Composable retry policies with fixed and exponential backoff |
| [`@zap-studio/validation`](/validation) | Standard Schema utilities and consistent validation errors |
| [`@zap-studio/webhooks`](/webhooks) | Webhook routing, signature verification, and payload validation |
