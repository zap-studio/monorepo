# $fetch

`$fetch` is the lowest-level public API. It behaves like native `fetch` when no schema is provided, and parses and validates JSON responses when a Standard Schema is provided.

## Signature

```ts
// Raw mode: no schema, resolves to the native Response
function $fetch(
  input: FetchInput,
  options?: ExtendedRequestInit
): Promise<Response>;

// Validated mode: resolves to data inferred from the schema
function $fetch<TSchema extends StandardSchemaV1>(
  input: FetchInput,
  schema: TSchema,
  options?: ExtendedRequestInit & { throwOnValidationError?: true }
): Promise<StandardSchemaV1.InferOutput<TSchema>>;

// Result mode: resolves to the Standard Schema result object
function $fetch<TSchema extends StandardSchemaV1>(
  input: FetchInput,
  schema: TSchema,
  options: ExtendedRequestInit & { throwOnValidationError: false }
): Promise<StandardSchemaV1.Result<StandardSchemaV1.InferOutput<TSchema>>>;
```

- `input` — a `string`, `URL`, or `Request`, the same type as global `fetch`.
- `schema` — any object implementing Standard Schema (Zod, Valibot, ArkType, ...).
- `options` — native `RequestInit` plus the extra options listed below.

The `FetchInput` and `ExtendedRequestInit` types are exported from `@zap-studio/fetch`; `StandardSchemaV1` is exported from `@zap-studio/validation`.

## Raw Response Mode

Call `$fetch(input, options)` without a schema to receive the native `Response`.

```ts
import { $fetch } from "@zap-studio/fetch";

const response = await $fetch("https://api.example.com/health");

console.log(response.status);
console.log(response.headers.get("content-type"));
```

Use this mode for headers, status codes, streams, text, blobs, or any response that should not be parsed as JSON by the package. Non-2xx responses still throw a `FetchError` unless you set `throwOnFetchError: false`.

## Validated Mode

Call `$fetch(input, schema, options)` to parse `response.json()` and validate the parsed value.

```ts
import { $fetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
});

const user = await $fetch("https://api.example.com/users/1", UserSchema);
```

The return type is inferred from the schema. The schema validates the response body only — never the request `json` or `body` options.

## Request Inputs

The `input` argument accepts a `string`, `URL`, or `Request` — the same type as global `fetch`. The `FetchInput` type is available from `@zap-studio/fetch`.

```ts
import { $fetch } from "@zap-studio/fetch";
import type { FetchInput } from "@zap-studio/fetch";

const input: FetchInput = new URL("https://api.example.com/users/1");
const response = await $fetch(input);
```

When `input` is a `Request`, its headers are merged with per-request `headers` (per-request values win), and remaining options are applied on top:

```ts
import { $fetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({ id: z.number(), name: z.string() });

const request = new Request("https://api.example.com/users/1", {
  headers: {
    Authorization: `Bearer ${process.env.API_TOKEN}`,
  },
});

const user = await $fetch(request, UserSchema);
```

## Options

`$fetch` accepts every standard `RequestInit` option (`method`, `headers`, `body`, `signal`, ...) plus the following:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `json` | `unknown` | `undefined` | JSON-stringified into `body`; sets `Content-Type: application/json` when no content type is already set. Mutually exclusive with `body`. |
| `searchParams` | `URLSearchParams` init | `undefined` | Per-request query params, merged into the request URL. |
| `throwOnFetchError` | `boolean` | `true` | Throw a `FetchError` on non-2xx responses. |
| `throwOnValidationError` | `boolean` | `true` | Throw a `ValidationError` when schema validation returns issues. When `false`, the Standard Schema result object is returned instead. |

Providing both `body` and `json` throws a `TypeError`.

```ts
import { $fetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({ id: z.number(), name: z.string() });

const user = await $fetch("https://api.example.com/users", UserSchema, {
  method: "POST",
  json: {
    name: "Ada",
  },
});
```

Here `UserSchema` validates the response. The `json` value is the outgoing request payload.

## Query Params

`searchParams` accepts the same inputs as `new URLSearchParams(...)` — an object, a string, entry pairs, or an existing `URLSearchParams`.

```ts
import { $fetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserListSchema = z.array(z.object({ id: z.number(), name: z.string() }));

await $fetch("https://api.example.com/users", UserListSchema, {
  searchParams: { page: "1", limit: "20" },
});

await $fetch("https://api.example.com/users", UserListSchema, {
  searchParams: new URLSearchParams({ q: "ada" }),
});

await $fetch("https://api.example.com/users", UserListSchema, {
  searchParams: "q=ada&page=1",
});
```

Per-request `searchParams` override params already present in the URL when keys overlap.

## Non-Throw Validation

Set `throwOnValidationError: false` to receive the raw Standard Schema result object instead of throwing.

```ts
import { $fetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({ id: z.number(), name: z.string() });

const result = await $fetch("https://api.example.com/users/1", UserSchema, {
  throwOnValidationError: false,
});

if (result.issues) {
  console.error(result.issues);
} else {
  console.log(result.value);
}
```

## Thrown Errors

| Error | Thrown when |
| --- | --- |
| `FetchError` | `throwOnFetchError` is `true` and the response is not ok. |
| `ValidationError` | A schema is provided, validation returns issues, and `throwOnValidationError` is `true`. |
| `TypeError` | Both `body` and `json` are provided, request construction fails, headers or search params are invalid, or the runtime `fetch` rejects a network failure. |
| `SyntaxError` | A schema is provided and `response.json()` cannot parse the body. |
| `DOMException` | The request or body read is aborted (`AbortError`). |

See [Error Handling](/fetch/errors) for catch patterns and error properties.
