# Result-Returning Variant

`$fetchResult`/`apiResult` are additive alternatives to [`$fetch`](/fetch/validated-fetch-mode)/[`api`](/fetch/api-methods) for consumers who prefer explicit [`Result`](/monads/result)/[`ResultAsync`](/monads/result-async) values over throw/catch. `$fetch`, `api`, and `createFetch(...)` are unchanged.

```ts
import { isOk } from "@zap-studio/monads";
import { apiResult } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({ id: z.number(), name: z.string() });

const result = await apiResult.get("https://api.example.com/users/1", UserSchema);

if (isOk(result)) {
  console.log(result.value);
} else {
  console.error(result.error); // FetchError | ValidationError
}
```

There's no `throwOnFetchError`/`throwOnValidationError` option — these always return a `Result`, so the flags don't apply. A non-ok response and validation issues both become `Err`; a malformed schema or request (a `TypeError`, `DOMException`, `SyntaxError`, or an unknown validator throw) still throws, since that's a programmer error, not a value to branch on.

## $fetchResult

Mirrors [`$fetch`](/fetch/validated-fetch-mode): call it with a schema to validate the response, or without one to get the raw `Response`.

```ts
import { $fetchResult } from "@zap-studio/fetch";

// With a schema
const result = await $fetchResult("/api/users/1", UserSchema);

// Without a schema — Ok wraps the raw Response, Err still covers a non-ok status
const response = await $fetchResult("/api/users/1");
```

## apiResult

Mirrors [`api`](/fetch/api-methods): `apiResult.get`, `apiResult.post`, `apiResult.put`, `apiResult.patch`, and `apiResult.delete`, each bound to their HTTP method.

```ts
import { apiResult } from "@zap-studio/fetch";

const created = await apiResult.post("/api/users", UserSchema, {
  json: { name: "Ada", email: "ada@example.com" },
});
```

## Configured Clients

`createFetch(...)` instances get `$fetchResult`/`apiResult` alongside `$fetch`/`api`:

```ts
import { createFetch } from "@zap-studio/fetch";

const { apiResult } = createFetch({ baseURL: "https://api.example.com" });

const result = await apiResult.get("/users/1", UserSchema);
```

## What Becomes Err

- **`FetchError`** — the response is not ok. Checked before the body is read, so a non-ok response with a schema provided produces `Err(FetchError)` without attempting to parse or validate the body — same order as `$fetch`'s throw mode.
- **`ValidationError`** — a schema is provided and validation returns issues.

```ts
import { FetchError } from "@zap-studio/fetch";
import { ValidationError } from "@zap-studio/validation";

if (!isOk(result)) {
  if (result.error instanceof FetchError) {
    console.error(result.error.status);
  } else if (result.error instanceof ValidationError) {
    console.error(result.error.issues);
  }
}
```

See [Structured Errors](/fetch/errors) for the full `FetchError`/`ValidationError` shapes, and [Result-Returning Variants](/validation/result) for `@zap-studio/validation`'s own `Result` API that this composes with internally.

## Chaining Before Awaiting

`$fetchResult`/`apiResult` return a [`ResultAsync`](/monads/result-async), so they're awaitable directly like the examples above, or chainable before awaiting:

```ts
const name = await apiResult
  .get("/api/users/1", UserSchema)
  .map((user) => user.name)
  .unwrapOr("anonymous");
```
