# Getting Started

## Installation

:::code-group

```bash [npm]
npm install @zap-studio/fetch
```

```bash [yarn]
yarn add @zap-studio/fetch
```

```bash [pnpm]
pnpm add @zap-studio/fetch
```

```bash [bun]
bun add @zap-studio/fetch
```

```bash [deno]
deno add jsr:@zap-studio/fetch
```

:::

You also need a schema library that implements [Standard Schema](https://standardschema.dev/schema), such as Zod, Valibot, or ArkType. The examples below use Zod.

## Your First Request

Start by describing the response shape you expect with a schema:

```ts
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.string().email(),
});
```

Then pass the schema as the second argument to an `api` method helper:

```ts
import { api } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.string().email(),
});

const user = await api.get("https://api.example.com/users/1", UserSchema);

console.log(user.email);
```

## What You Get

- `user` is typed as `{ id: number; name: string; email: string }`, inferred from the schema — no manual type annotations or `as` casts.
- The response body is parsed with `response.json()` and validated at runtime. A mismatched response throws a `ValidationError`.
- A non-2xx response throws a `FetchError` before validation runs.

:::note The schema validates the **response** body returned by the server. It never validates outgoing request payloads. :::

## Send JSON

Use the `json` option to send a JSON request body. The package serializes it with `JSON.stringify` and sets `Content-Type: application/json` unless a content type is already set.

```ts
import { api } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.string().email(),
});

const created = await api.post("https://api.example.com/users", UserSchema, {
  json: {
    name: "Ada",
    email: "ada@example.com",
  },
});
```

Here `UserSchema` validates the server's response. The `json` object is the outgoing request body and is not validated by the schema. `json` and the native `body` option are mutually exclusive — providing both throws a `TypeError`.

## Raw Responses

Use `$fetch` without a schema when you need the native `Response` object:

```ts
import { $fetch } from "@zap-studio/fetch";

const response = await $fetch("https://api.example.com/health");

console.log(response.status);
```

## Configured Client

Use `createFetch` when many requests share a base URL, headers, or query params:

```ts
import { createFetch } from "@zap-studio/fetch";
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
});

const { api } = createFetch({
  baseURL: "https://api.example.com",
  headers: {
    Authorization: `Bearer ${process.env.API_TOKEN}`,
  },
});

const user = await api.get("/users/1", UserSchema);
```
