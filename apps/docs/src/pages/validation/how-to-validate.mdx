# How to Validate

This page shows how to validate data against a Standard Schema. If you are new to schema validation, read [Concepts](/validation/concepts) first.

All examples use this schema, but any [Standard Schema](https://standardschema.dev)-compatible library works:

```ts
import { z } from "zod";

const userSchema = z.object({
  name: z.string(),
  age: z.number(),
});
```

## Validate Asynchronously

Use `standardValidate` as the default choice. It works with both synchronous and asynchronous schemas, so one API covers both cases.

By default it does not throw. It returns the raw Standard Schema result: an object with either `value` (success) or `issues` (failure).

```ts
import { standardValidate } from "@zap-studio/validation";

const result = await standardValidate(userSchema, input);

if (result.issues) {
  console.error("Validation failed", result.issues);
} else {
  console.log("Validation passed", result.value);
}
```

## Throw on Error

Pass `throwOnError: true` when invalid input should stop execution. The helper then returns the parsed value directly and throws a `ValidationError` on failure.

```ts
import { standardValidate } from "@zap-studio/validation";

const user = await standardValidate(userSchema, input, {
  throwOnError: true,
});

console.log(user.name); // typed as the schema's output
```

See [Handling Errors](/validation/handling-errors) for how to catch and inspect the error.

## Validate Synchronously

Use `standardValidateSync` only when validation must remain synchronous end-to-end, for example in sync-only code paths or constrained runtimes.

```ts
import { standardValidateSync } from "@zap-studio/validation";

const result = standardValidateSync(userSchema, input);

if (result.issues) {
  console.error("Validation failed", result.issues);
} else {
  console.log("Validation passed", result.value);
}
```

It supports the same `throwOnError` option:

```ts
const user = standardValidateSync(userSchema, input, {
  throwOnError: true,
});
```

:::warning[Async Schemas] If the schema validates asynchronously, `standardValidateSync` throws a `TypeError` with the message `Async schemas are not supported by standardValidateSync`. :::

:::tip Prefer `standardValidate` by default. It is the most compatible option because it supports both sync and async schemas. :::

## Choose the Right Helper

| Helper | Sync schemas | Async schemas | Returns | Best use case |
| --- | --- | --- | --- | --- |
| `standardValidate` | Yes | Yes | `Promise` of result or parsed value | Default choice for most applications |
| `standardValidateSync` | Yes | No | Result or parsed value directly | Strict sync-only requirements |

- Use `standardValidate` by default for compatibility and simpler call sites.
- Use `standardValidateSync` only when synchronous behavior is a hard requirement.

## Reuse a Validator

If you validate many values against the same schema, prefer `createStandardValidator` or `createSyncStandardValidator`. The returned validator functions support the same `throwOnError` modes. See [Create Validators](/validation/create-validators).
