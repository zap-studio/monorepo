# Result-Returning Variant

`runRetryPolicyResult(policy, execute, options?)` is an additive alternative to [`runRetryPolicy`](/retry/running-policies) for consumers who prefer explicit [`Result`](/monads/result)/[`ResultAsync`](/monads/result-async) values over throw/catch. `runRetryPolicy` (both throw mode and [non-throw mode](/retry/non-throw-mode)) is unchanged.

```ts
import { isOk } from "@zap-studio/monads";
import { exponentialBackoff, runRetryPolicyResult } from "@zap-studio/retry";

const policy = exponentialBackoff({
  maxAttempts: 5,
  baseDelayMs: 100,
  maxDelayMs: 2_000,
});

const result = await runRetryPolicyResult(policy, async () => {
  return await doWork();
});

if (isOk(result)) {
  console.log(result.value);
} else {
  console.error(result.error);
}
```

There's no `throwOnExhausted` option — `runRetryPolicyResult` always returns a `Result`, so the flag doesn't apply. Every other [run option](/retry/running-policies#run-options) (`sleep`, `signal`, `logger`) works the same as `runRetryPolicy`.

## Chaining Before Awaiting

`runRetryPolicyResult` returns a [`ResultAsync<T, RetryError | AbortError>`](/monads/result-async), so it's awaitable directly like the example above, or chainable before awaiting:

```ts
const label = await runRetryPolicyResult(policy, doWork)
  .map((value) => `done: ${value}`)
  .unwrapOr("failed");
```

## What Becomes Err

`Err`'s payload is the same [`RetryError`/`AbortError`](/retry/errors) object `runRetryPolicy`'s throw mode would throw — not a separate wrapper type:

- **`RetryError`** — retries exhausted, or a caught value `policy.isKnownError` rejected as outside its error domain (see [Narrow the Error Domain](/retry/custom-policies#narrow-the-error-domain)). `attempts`, `lastError`, and `lastData` are preserved.
- **`AbortError`** — the run was canceled through `AbortSignal`. `cause` is preserved when the abort reason was an `Error`.

```ts
import { AbortError, RetryError } from "@zap-studio/retry";

if (!isOk(result)) {
  if (result.error instanceof RetryError) {
    console.error("Attempts:", result.error.attempts);
  } else if (result.error instanceof AbortError) {
    console.error("Aborted:", result.error.message);
  }
}
```

Unlike [non-throw mode](/retry/non-throw-mode)'s `RetryRunResult`, there's no separate top-level `attempts` field on the failure branch — `RetryError` already carries `attempts` on itself, so `Err(error)` alone is the full picture.
