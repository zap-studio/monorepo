# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0]

### Added

- **State** (`state/`) — `useCredential`. It wraps the Credential Management API (`navigator.credentials`) for sign-in and sign-out in code.
- **Sensors** (`sensors/`) — `useBrowserEngine`. It finds `"blink"`, `"gecko"`, or `"webkit"` with feature checks, not by reading `navigator.userAgent`. Use it for a rare cross-engine problem that no single feature check can solve, like Safari's `requestPermission()` gesture for `useDeviceOrientation`/`useDeviceMotion`.
- **Media** (`media/`) — `useExperimentalBarcodeDetector` (Barcode Detection API) and `useExperimentalSelectAudioOutput` (pick an audio output device).
- **DOM / element interaction** (`dom/`) — `useExperimentalContactPicker` (Contact Picker API).
- **Sensors** (`sensors/`) — `useExperimentalIdleDetector` (Idle Detection API), `useExperimentalLocalFonts` (Local Font Access API), and the Generic Sensor API group: `useExperimentalAccelerometer`, `useExperimentalLinearAccelerationSensor`, `useExperimentalGravitySensor`, `useExperimentalGyroscope`, `useExperimentalMagnetometer`, `useExperimentalAbsoluteOrientationSensor`, `useExperimentalRelativeOrientationSensor`, `useExperimentalAmbientLightSensor`.
- **Sensors** (`sensors/`) — `useExperimentalNfc`. It wraps the Web NFC API's `NDEFReader`, to scan, write, and lock NDEF tags.
- **Sensors** (`sensors/`) — `useExperimentalWindowManagement`. It wraps the Window Management API (`window.getScreenDetails()`) for multi-screen layouts, and adds an `isExtended` flag that needs no permission.
- **Network** (`network/`) — `useWebTransport`. It wraps the WebTransport API for HTTP/3 datagrams and reliable streams, next to `useWebSocket`/`useEventSource`.
- **Lifecycle** (`lifecycle/`) — `useIsomorphicLayoutEffect`. It runs `useLayoutEffect` on the client and `useEffect` on the server, so a pre-paint effect does not warn during server rendering.
- **Debug** (`debug/`) — `useUnstableFiber` and `useUnstableRenderReason` now take an `options.maxWalk` value. It limits how many Fiber ancestors, hooks, or context entries they check before they stop, for a component tree deeper than the default of 50.

### Fixed

- **Untyped `MessageEvent` casts** — `useEventSource` and `useWindowMessage` used an `as` cast on `event.data` inside the handler. Now the handler's `event` parameter has the type `MessageEvent<string>`/`MessageEvent<T>`, so `event.data` already has the right type, no cast needed.
- **Ref targets were read only once** — `useIntersectionObserver`, `useResizeObserver`, `useHover`, `useFileDrop`, `useMutationObserver`, `usePopover`, and `usePictureInPicture` read `ref.current` one time, at mount. If the element came later, changed, or was rendered only sometimes, the hook never saw it, and setting the ref back to `null` never stopped anything. They now read `ref.current` again on every commit.
- **Unattached refs matched `null` by mistake** — `useFullscreen` and `usePointerLock` checked `document.fullscreenElement`/`pointerLockElement` against `ref.current`, but `ref.current` can be `null` too, so they reported `true` whenever any other element left fullscreen or the pointer lock. `usePictureInPicture`'s `exit()` had the same bug: it called `exitPictureInPicture()` even when its own ref had no element.
- **Options objects were compared by identity, not by value** — `usePerformanceObserver` rebuilt its observer on every render for an inline `options` object, sending the whole entry buffer again under `buffered: true`. `useIdleCallback` cancelled and asked again on every render, which could block a callback meant to fire only once. `useIntersectionObserver`, `useMutationObserver`, `useKeyPress`, `useMediaRecorder`, `useScreenCapture`, `useUserMedia`, `useCamera`, `useWebLock`, `useExperimentalBarcodeDetector`, and `useLocalStorage`/`useSessionStorage` had the same problem for an unmemoized argument. None of them rebuild their subscription or their returned callbacks for this reason anymore.
- **Debug hooks** — `useUnstableFiber` read its element during render, so `fiber` stayed `null` after mount until some unrelated re-render happened. `useIsFirstRender` flipped its ref during render too: in StrictMode, React throws away the first render pass, so it threw away the `true` value, and the render that stayed showed `false`.
- **Stale "latest value" refs in fast events** — `useNavigationBlocker`, `usePageLeave`, `useWindowMessage`, `useThrottle`, and `useLocalStorage`/`useSessionStorage` updated their "latest callback/value" ref inside a passive effect. A `navigate`/`mouseout`/`message`/`storage` event can fire on its own, not tied to this component's render, and the same is true when you call the function `useThrottle` returns directly. If one of these fired before the passive effect ran, the hook read the value from the render before. They now update the ref in a layout effect instead, so this gap is closed.
- **Unmemoized result objects** — `useGenericSensor` (used by every `useExperimental*Sensor` hook), `useDeviceMotion`, `useDeviceOrientation`, `useExperimentalIdleDetector`, `useExperimentalLocalFonts`, `useExperimentalContactPicker`, `useExperimentalEyeDropper`, `useFilePicker`, and `useViewTransition` built a new object on every render, even though every field inside was already stable (a `useCallback` or a plain value). If a caller kept the whole object — as a `useEffect`/`useMemo` dependency, a prop on a `React.memo`'d child, or a context value — it re-ran or re-rendered on every unrelated parent render. All nine now wrap their return value in `useMemo`.
- **Stream kept running after unmount** — `useUserMedia`, `useCamera`, and `useScreenCapture` called `getUserMedia()`/`getDisplayMedia()` and set the stream only once the promise resolved. If the component unmounted while that promise was still pending, cleanup ran too early to stop anything, so the camera, mic, or screen share kept running once the stream arrived. All three now check if the component is still mounted before keeping the stream, and stop it right away if not.
- **`useScreenCapture` missed the end of audio-only captures** — it listened for `ended` on `getVideoTracks()[0]`, so an audio-only capture (no video track) never got a listener, and `status` stayed `"active"` after the share ended. It now listens for `inactive` on the `MediaStream` itself, which fires once every track has ended, no matter the track type or count.
- **Async work and cleanup mixed in one effect** — `useBattery` and `usePermission` awaited their async resource inside the same mount effect that then called `addEventListener`, passing the eventual `removeEventListener` call through a mutable `cleanup` variable held across the `await`. Both now use two effects: one turns the async resource into state, the other attaches and detaches the listener once that state is set, so cleanup no longer depends on a variable held across an `await`.
- **Listeners attached outside an effect, with no cleanup lint could see** — `useMediaRecorder`, `useSpeechSynthesis`, `useExperimentalIdleDetector`, `useExperimentalNfc`, `useExperimentalWindowManagement`, and `useWakeLock` built their `MediaRecorder`/utterance/detector/reader/`ScreenDetails`/sentinel inside a callback the user calls (`start()`, `speak()`, `scan()`, `requestPermission()`, `request()`), and attached listeners to it right there, using a `cleanupRef` instead of an effect's own cleanup (`useMediaRecorder`/`useSpeechSynthesis` had no ref for it at all) — each needed an `oxlint-disable-next-line react-doctor/effect-needs-cleanup` comment to explain why. All six now store that resource in state instead, and a second effect, keyed on it, attaches the listeners and returns their removal (plus `AbortController.abort()` where one already guarded the call), so cleanup is a normal effect return and the disable comments are gone. `useSpeechSynthesis` also moved its `window.speechSynthesis.speak()` call into that effect, after the listeners attach, since a queued utterance's `start` event can fire right away and would otherwise be missed.
- **`useIndexedDB` rejected with a `null` error** — `openDatabase`, `getValue`, `putValue`, and `deleteValue` rejected with `request.error`/`tx.error` directly, and the DOM types allow both to be `null`. When one was `null`, the rejection carried no error object, and the `String(caught)` fallback turned it into `Error("null")` in the hook's `error` state. All four now reject with an `Error` that describes what failed, for when the platform gives none.
- **Capability checks needed a lint suppression to avoid a hydration mismatch** — `useStorageEstimate`, `useFontsReady`, `useGeolocation`, `useIndexedDB`, and `usePermission` each checked for a missing browser API (`navigator.storage`, `document.fonts`, `navigator.geolocation`, `indexedDB`, `navigator.permissions`) inside a mount effect, then called `setState` to move from the safe server default to the real value — exactly the case `useSyncExternalStore`'s `getServerSnapshot` is built for. All five now get their browser-support flag from `useIsClient()` (the package's own `useSyncExternalStore`-based hydration check) and compute the unsupported result during render instead. The `react/set-state-in-effect` suppression is gone, mount does one less render when the API is missing, and each hook still returns the same thing as before.
- **`useScript` re-synced its status with an extra `setState` call** — each call kept `status` in its own `useState`, then read the shared script-registry entry's status again inside its mount effect, to catch a script that another instance had already finished loading, needing a lint suppression to explain why. It now reads the entry's status directly through `useSyncExternalStore`, so every instance sharing the same `src` reads the same status straight from the registry, with no local state to fall out of sync and no manual re-sync call needed.

### Changed

- **DOM / element interaction** (`dom/`) — `useClickOutside`, `useHotkeys`, `useHover`, `useFileDrop`, `usePointer`, and `useLockBodyScroll` now attach in a layout effect instead of a passive one, closing a gap where an event between paint and the passive effect could be missed: a swallowed outside click, a `keydown` that loses its `preventDefault()`, a stuck `mouseleave`/`pointerup`, a one-shot `drop`, or a frame where the background behind a modal could still scroll.
- **DOM / element interaction** (`dom/`) — `useEventListener` now attaches in a layout effect instead of a passive one, for the same reason: an event between paint and the passive effect can no longer be missed. Its `options` argument is now compared field by field, not by identity, so an inline object no longer causes a re-subscribe on every render. A `RefObject` target's `current` is now read again on every commit, so a ref that is `null` on the first render, or that later points at a different element, is now picked up.
- **Debug** (`debug/`) — Renamed `useUnstableRenderCount` → `useRenderCount`, `useUnstableWhyDidYouUpdate` → `useWhyDidYouUpdate`, `useUnstableIsFirstRender` → `useIsFirstRender`, `useUnstableRenderDuration` → `useRenderDuration` (and `UseUnstableRenderDurationResult` → `UseRenderDurationResult`), and `useUnstableOwnerStack` → `useOwnerStack` (and `UseUnstableOwnerStackResult` → `UseOwnerStackResult`). None of these read react-dom's private Fiber internals — only `useUnstableFiber` and `useUnstableRenderReason` do, so only those two keep the `Unstable` name. **Breaking rename.**
- **DOM / element interaction** (`dom/`) and **Sensors** (`sensors/`) — Renamed `useEyeDropper` → `useExperimentalEyeDropper`, `useUserAgentData` → `useExperimentalUserAgentData`, and `useVirtualKeyboard` → `useExperimentalVirtualKeyboard` (and `UseEyeDropperResult` → `UseExperimentalEyeDropperResult`). MDN marks the EyeDropper API, the User-Agent Client Hints API, and the VirtualKeyboard API as "Experimental," so these names now match every other `useExperimental*` hook in the package. **Breaking rename.**
- **Docs** — The README and the docs site now explain `Unstable` and `Experimental` more clearly: `Unstable` means the hook could break on a React upgrade, because it reads private Fiber internals; `Experimental` means the browser API itself could change, or may not ship in every browser. Inline TSDoc comments across the package (the text editors show on hover) are also simpler now, and we removed notes that should not have been there: links to other packages, and a repeated "not a public hook" note.
- **Input** (`input/`) — `useGamepad` now returns real [`Gamepad`](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad) objects instead of the short `GamepadInfo` type (`id`/`index`/`mapping` only), giving you `axes`, `buttons`, `connected`, `timestamp`, and `hapticActuators`/`vibrationActuator` directly. `GamepadInfo` is removed. **Breaking change.**
- **State** (`state/`) — `useLocalStorage`/`useSessionStorage` now return a 4th tuple value: the error from the last failed read, write, or remove (quota full, private browsing, bad JSON), or `null` if there was none. Before, these errors were silent, and you could only see them as a fallback to `initialValue`.
- **Lifecycle** (`lifecycle/`) — `useMount` and `useAsync` now hold `effect`/`asyncFn` in a ref instead of using a `react-hooks/exhaustive-deps` lint-disable. Same behavior, but the lint rule is satisfied without a suppression.
- **Type assertions replaced with real checks** — the `as` casts that told the compiler to trust something it could not check are gone, with no change in behavior. The only casts left widen a global (`window`, `navigator`) with optional fields for a feature check, which stays checked at runtime. Event handlers are now typed at the parameter instead of cast in the body (`usePopover`'s `ToggleEvent`, `useNavigationBlocker`'s `NavigateEvent`, `useExperimentalNfc`'s `NDEFReadingEvent`, backed by a new `addEventListener`/`removeEventListener` overload pair on the internal `NDEFReader` type). `useNavigationType` now checks `performance.getEntriesByType("navigation")` by its `entryType` field, instead of asserting the array's element type. `useWebTransport` now types its datagram reader as `ReadableStreamDefaultReader<Uint8Array>` at the `getReader()` call, so chunks are no longer `any`. The Generic Sensor API lookup now keys `window` with the exact eight constructor names it can ask for, instead of an index signature over `unknown`. `useHistoryState` now checks its undo/redo stacks with a non-empty-tuple check instead of asserting the head item is defined (both stacks are now stored newest-first, so the head is the item undo/redo needs).
- **State** (`state/`) — `useLocalStorage`/`useSessionStorage`, `useIndexedDB`, `useHistoryState`, and `useSearchParams` now check their `value | (prev) => value` setter argument with one shared `isUpdaterFunction` type check, replacing four separate copies of a `typeof next === "function"` check that each had to assert the function type again afterward. Same setter API, same behavior.
