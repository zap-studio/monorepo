# Scaffold package

## Package anatomy

Each `packages/<name>` has `src/`, `package.json`, `jsr.json`, `tsconfig.json`, `CHANGELOG.md`, `README.md`, `LICENSE`.

| File / rule                   | What to know                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `tsconfig.json`               | Turns on `isolatedDeclarations`: every exported symbol needs an explicit type. No inferred public types.               |
| `package.json` exports / dist | Generated by the build tool. Do not hand-edit the `exports` map. Add a source file and rebuild instead.                |
| `src/**/_*.ts`                | Private helpers, left out of the public build. Use the `_` prefix for anything that is not part of the public API.     |
| `jsr.json`                    | Mirrors `package.json`: keep `version` in sync, and its `exports` point at `src/*.ts`, not `dist`. Bump both together. |
| Module format                 | ESM-only, no side effects, framework-neutral. Avoid Node built-ins unless the package targets Node.                    |

## Adding a dependency

Add it to the shared catalog in `pnpm-workspace.yaml` first, then reference `"catalog:"` in the package's `package.json`. `pnpm run fallow` fails on unused dependencies and unused exports — real false positives go in `.fallowrc.json`, not in a disabled check.

## Code style for new source files

- Relative imports carry the `.ts` extension (`./use-counter.ts`).
- `import type` for type-only imports.
- Arrow-function consts for exported functions and hooks, kebab-case file names, `use-*.ts` for React hooks.
- TSDoc on every exported symbol, and a `@module` block on the package entry point. Write what the thing does and its non-obvious constraint, not a restatement of the signature.
